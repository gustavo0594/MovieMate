01 · Overview

What the app is, and isn’t

MovieMate is not a TMDB browser with a watchlist bolted on. Its job is to answer one question — what should I watch tonight? — using a memory of what the viewer has actually watched, rated, and saved. TMDB is the encyclopedia; Room is the diary; the Prompt API is the friend who has read the diary and picks from a shelf of movies that actually exist.

In scope for MVP

Discover, search, and inspect movies via TMDB · favorite / watch / watchlist any movie · optional 1–5 star personal rating · trailers · a local candidate catalog of 500–2,000 titles · on-device “Surprise Me” recommendations with a stated reason.

Explicitly out of scope

Accounts, cloud sync, a custom backend, TV shows, streaming availability, social features, and any server-side ML. Everything the app knows about the user lives only in that device’s Room database.

Design thesis

Every screen and every data decision below optimizes for one loop: watch → rate → the next recommendation gets sharper. If a feature doesn’t feed that loop or help the user act on tonight’s pick, it doesn’t belong on Home.

02 · Architecture

Clean architecture, three layers, one direction of dependency

Presentation and data both depend inward on domain; domain depends on nothing. This is what makes the recommendation engine swappable later (a different on-device model, or eventually a server) without touching a single Composable.

03 · Local-First Flow

From TMDB metadata to a recommendation, end to end

Two things get cached from TMDB: catalog metadata (facts about a movie) and the user’s relationship to it (a fact only this device knows). The candidate builder joins them before the model ever runs.

Core rule

The Prompt API never free-generates a title. It is handed a numbered list of real candidate movies and must answer with an ID from that list. See §07 for how this is enforced.

04 · Navigation Model

Four primary destinations, three secondary flows

Primary destinations are the ones a viewer returns to daily: Home, Watchlist, Favorites, Watched. Everything else — Search, Movie Details, the recommendation screen, the trailer player — is reached by drilling in, not by a nav destination of its own, so the primary nav stays at exactly four items on every device class.

Primary persistent nav

Home · Watchlist · Favorites · Watched. Rendered by a single NavigationSuiteScaffold, which is what actually changes shape across device sizes (§05) — the destinations themselves never change.

Secondary pushed / overlay

Search (top-bar entry point from any primary tab) · Movie Details · Surprise Me / Recommendation · Trailer player (full-screen player, dismissable).

05 · Adaptive Layout

One codebase, three window size classes

The app is built around Material 3’s adaptive layer (WindowSizeClass + NavigationSuiteScaffold + ListDetailPaneScaffold) rather than separate phone/tablet flavors. The same navigation graph and the same screen composables render differently depending on available width — including the two panes of an unfolded foldable, which report as Medium or Expanded the moment the hinge opens.

Foldable posture

On a foldable in table-top or book posture, WindowInfoTracker reports the hinge as a physical feature. The layout treats it like a hard gutter: on a book-posture unfold, the nav rail + list live on one leaf and the detail pane on the other, so no card or button is ever split by the crease.

06 · Screen Designs

Screen by screen, compact vs. expanded

Home P0

Top: Surprise Me hero card — full-width, high-contrast, one tap to the recommendation screen. Below: short, TMDB-powered rows — Picked for You, Popular, Top Rated, Now Playing, Upcoming. Capped at five rows so Home reads as curated, not as a database dump.

Compact vertically scrolling rows, horizontally scrolling carousels inside each.
Expanded hero spans the content pane full width; rows below reflow into a responsive poster grid instead of horizontal carousels, since width allows it.

Search P0

Top app bar search field → TMDB search results as a poster grid/list. Selecting a result opens Movie Details. Every result supports the same quick actions as Home: favorite, watchlist, mark watched.

Compact results replace the screen; Details is pushed full-screen.
Expanded results list is the fixed list pane; Details renders live in the pane beside it as selection changes — no navigation transition.

Movie Details P0

Backdrop with poster overlap, title, release year, runtime, TMDB rating, genres, overview, cast row, director, trailer entry point, similar-movies row. Action row: Favorite · Watchlist · Mark Watched · Watch Trailer. If already watched, the user’s own star rating replaces the “Mark Watched” affordance.

Compact single scrolling column, full-bleed backdrop.
Expanded (as a pane) backdrop shortens to a header strip so the pane isn’t dominated by imagery; actions and metadata sit in a fixed side column while cast/similar scroll.

Favorites · Watchlist · Watched P0

Same list component, three filtered views over one underlying store — a movie can appear in more than one. Watched cards additionally surface the star rating and watched date; Watchlist and Favorites are unordered poster grids with a status chip.

Compact 2-column poster grid.
Medium 3–4 columns.
Expanded 5–6 columns, or a list-detail pane so tapping a poster opens Details beside the grid instead of covering it.

Surprise Me / Recommendation P1

One large “your pick” card — poster, title, match percentage — with a “Why this movie?” panel underneath naming the rated movies and taste signals behind it. A secondary row offers 2–3 runner-up candidates.

Compact pick card, then explanation, then runners-up, stacked.
Expanded two-pane: pick + poster large on the left, explanation and runners-up in a fixed right rail — closer to a verdict screen than a list.

Trailer Player P1

Full-screen video surface (ExoPlayer/YouTube playback from the TMDB video key), auto-rotates with device orientation, dismiss returns to exactly where Details was scrolled to.

Compact full-screen modal, forces landscape for playback.
Expanded can play inline within the Details pane at native aspect ratio instead of taking over the whole window.
07 · Recommendation Engine

Closed-set selection with a validation guard

An on-device generative model can still name a movie that isn’t in the candidate set, or misquote an ID. The app never trusts the raw response — every result is checked against the candidate list before it reaches the UI.

  • Inputs: watched history, personal ratings (weighted above TMDB’s), favorites, watchlist, candidate genres/cast/directors/runtime/year/rating, and an optional free-text mood (“something funny tonight”).
  • Output contract: { movieId: Int, matchScore: Int, reason: String }, requested and parsed as structured JSON, never freeform prose.
  • Every recommendation is logged (movie, reason, score, timestamp, whether it was later watched/favorited) so the loop in §01 has a signal to learn from, not just a UI moment.
